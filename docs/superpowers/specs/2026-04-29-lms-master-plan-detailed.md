## 3) المراحل بالتفصيل (مرتبطة بـ `tasks.md`)

### المرحلة 1 — Foundation (T001–T005)

**الهدف:** قاعدة بيانات نظيفة + بيانات مرجعية قبل أي اختبار للميزات.

- تشغيل الترحيلات: `php artisan migrate` (أو `--force` في CI/الإنتاج حسب السياسة).
- بذر العملات: `SupportedCurrencySeeder` (EGP كمرجع، وأسعار صرف أولية للدول الأخرى).
- بذر الأدوار والصلاحيات: `RolePermissionSeeder`.
- التحقق: `php artisan migrate:status` — جداول التسعير، الموافقة، الـ affiliate إن وُجدت.

**نقطة تفتيش:** كل الترحيلات مطبّقة؛ الجداول المرجعية ممتلئة.

---

### المرحلة 2 — US1 واجهة إدارة خطط الاشتراك (T006–T011)

**الهدف:** الأدمن ينشئ/يعدّل/يعرض خطط الاشتراك من لوحة التحكم.

- تعديل الشريط الجانبي: قسم «الاشتراكات» مع `@can('subscription-plans-list')`.
- صفحات: `index` (إنشاء مضمّن + جدول)، `edit`، `show` (إحصاءات ومشتركين).
- `SubscriptionPlanSeeder`: خمس خطط افتراضية بالعربية مع JSON للمميزات.
- **T011:** تشغيل البذور على البيئة الفعلية.

**نقطة تفتيش:** مسار كامل CRUD من الواجهة بدون أخطاء صلاحيات.

---

### المرحلة 3 — US2 التجديد وواجهات API للخطة (T012–T018)

**الهدف:** API للتجديد؛ للأدمن: تفعيل/تعطيل، ترتيب، أسعار حسب الدولة؛ نفس السلوك عبر الويب و`/api/admin/...` حيث ينطبق.

- `POST /api/subscription/renew` مع خدمة الاشتراك.
- `toggle`, `updateSortOrder`, `setCountryPrices` في `SubscriptionPlanController`.
- تسجيل المسارات في `web.php` و`api.php` مع الحماية المناسبة.

**نقطة تفتيش:** استجابات JSON موحّدة؛ الصلاحيات `subscription-plans-edit` حيث يلزم.

---

### المرحلة 4 — US3 التسعير المحلي (T019–T020)

**الهدف:** عرض السعر بعملة المستخدم؛ إدخال أسعار لكل دولة من صفحة التعديل.

- `getPlans()` يضيف `display_price`, `display_currency`, `display_symbol`.
- قسم «أسعار الدول» في `edit.blade.php` مع حفظ عبر AJAX لـ `setCountryPrices`.

**نقطة تفتيش:** مقارنة استجابة API من سياقات دولة مختلفة (أو اختبار وحدات/تكامل إن وُجد).

---

### المرحلة 5 — US4 المشرفون والصلاحيات (T021–T024)

**الهدف:** مصطلح «مشرف» في الواجهة؛ تعيين صلاحيات دقيقة؛ فرضها في المتحكمات.

- إعادة تسمية النصوص فقط (المسارات تبقى كما هي إن كان ذلك هو القرار السابق).
- واجهة صناديق اختيار للصلاحيات مع `syncPermissions`.
- فحوصات `ResponseService::noAnyPermission...` على المتحكمات الحرجة.

**نقطة تفتيش:** مستخدم بصلاحيات جزئية يحصل على 403 على الموارد الممنوعة.

---

### المرحلة 6 — US5 سير عمل الموافقة (T025–T031)

**الهدف:** عند تفعيل الـ feature flag، التقييمات/التعليقات تظهر للعامة فقط بعد الموافقة.

- فلترة في API العامة؛ الحالة الافتراضية `pending` عند الإنشاء.
- `ApprovalController` + مسارات الويب والـ API + واجهة تبويبات + رابط في الشريط الجانبي.

**نقطة تفتيش:** عنصر معلّق لا يظهر في API العامة حتى الموافقة.

---

### المرحلة 8 — US6 الوصول للمحتوى وتقدم الفيديو (T039–T047)

**الهدف:** قاعدة 85% للدرس التالي؛ كورسات/دروس مجانية؛ مرفقات؛ أعلام ميزات.

- ترحيلات: تقدم المحاضرة، أعلام مجانية، مرفقات.
- خدمة تقدم/وصول؛ نقاط نهاية API؛ تطبيق القواعد قبل عرض الدرس التالي.
- مرفقات خلف feature flag.

**نقطة تفتيش:** تقدم يُسجَّل؛ منع الدرس التالي حتى تحقيق نسبة المشاهدة المطلوبة.

---

### المرحلة 9 — US7 التسويق بالعمولة (T048–T056)

**الهدف:** روابط إحالة، عمولة أول دفع، جدول إطلاق، سحوبات، واجهات أدمن؛ تعطيل النظام = 404 أو ما عرّفه العقد.

- نماذج وخدمة `AffiliateService`؛ ربط أول دفع اشتراك؛ أمر إطلاق العمولات؛ جدولة يومية.

**نقطة تفتيش:** مسار إحالة كامل من النقر حتى عمولة متاحة للسحب (حسب القواعد).

---

### المرحلة 10 — US8 الإشعارات والشهادات (T057–T062)

**الهدف:** تذكير انتهاء الاشتراك؛ معالجة المنتهية؛ شهادة مع QR وتحقق عام عند إكمال 100%.

- أوامر Artisan؛ قوالب بريد؛ تعديل خدمة الشهادة؛ مسار التحقق العام.

**نقطة تفتيش:** شهادة لا تُصدَر إلا عند اكتمال الدورة؛ QR يفتح صفحة تحقق صحيحة.

---

### المرحلة 11 — الجودة والتحقق النهائي (T032–T038)

**الهدف:** ربط كل الميزات في سيناريوهات حقيقية.

- **T033–T037** تتطلب **تطبيقاً يعملاً + دفع/ويب هوك** حيث ينطبق: سلسلة الاشتراك→العمولة→السحب، التسعير→Kashier، التقدم→الشهادة، أوامر الإشعارات، مصفوفة الصلاحيات.
- **T038:** linter نظيف على الملفات المعدّلة.

**نقطة تفتيش:** قائمة تحقق يدوية موقعة؛ جاهزية للإنتاج من منظور هذه الميزات.
